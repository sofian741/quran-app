# تقرير الأمان والخصوصية

**تاريخ المراجعة:** 2026-10-17

## الخلاصة

لم يظهر مفتاح API سري أو كود تنفيذي خارجي أو تتبع أو إعلان أو جمع بيانات لحساب مطور
التطبيق. أصلحت المراجعة غياب CSP و`no-referrer` وتفاوت تسجيل Service Worker. مستوى
المخاطر مناسب لاختبار ويب/Android داخلي بعد تطبيق إعدادات حاوية Capacitor المقترحة، مع
بقاء مخاطر المزودين وحقوق المحتوى والنشر الخارجي.

## سطح الهجوم والفحص

- كل JavaScript وCSS والخطوط الأساسية محلية؛ لا توجد CDN أو حزم npm وقت التشغيل.
- لا يستخدم الكود `eval` أو `new Function`.
- مواضع `innerHTML` تبني SVG وقوالب ثابتة يملكها المشروع. أسماء القراء ونتائج الشبكة
  توضع عبر `textContent`؛ لم يُعثر على إدخال شبكة غير موثوق يحقن HTML.
- الروابط التي تفتح تبويبًا جديدًا تحمل `noopener noreferrer`.
- كل عناوين التشغيل الشبكية الفعلية HTTPS. نصوص `http://` الباقية إشعارات ترخيص أو
  localhost وليست طلبات تشغيل غير آمنة.
- لا توجد مفاتيح أو رموز OAuth أو كلمات مرور. أضيف تجاهل `*.jks` و`*.keystore` وملفات
  خصائص التوقيع و`.env`.
- Service Worker يعترض GET فقط؛ يطبق cache-first على الصوت المحفوظ صراحة، وnetwork-first
  على ملفات الأصل نفسه، ويحذف إصدارات غلاف قديمة فقط. بيانات المستخدم لا تُحذف عند التحديث.
- CSP تمنع السكربتات والصور والخطوط البعيدة وتسمح HTTPS للصوت والاتصال. وجود
  `style-src 'unsafe-inline'` مطلوب حاليًا للأنماط المضمنة التي تتحكم في القياس والحركة.

## البيانات المخزنة محليًا

| المخزن | المحتوى | الحساسية/العمر |
|---|---|---|
| `localStorage` | الصفحة والثيم والمفضلة والفواصل وتقدم الأذكار وحالة الصوت وفهرس التنزيل | بيانات استخدام محلية منخفضة الحساسية، تبقى حتى مسح بيانات التطبيق. |
| IndexedDB | كاش قياسات تخطيط المصحف | مشتق تقني يمكن إعادة بنائه. |
| Cache Storage | غلاف التطبيق، بيانات وقت الطلب، وملفات الصوت التي اختارها المستخدم | قد يكون كبيرًا وقابلًا للإخلاء في WebView؛ يمكن حذفه من «مكتبتي» أو بيانات التطبيق. |

لا يملك المشروع خادمًا يستقبل هذه البيانات. الاتصال بمزود صوت أو API يكشف للمزود عنوان
IP وUser-Agent والمسار المطلوب وفق عمل HTTPS المعتاد. يجب ذكر ذلك في سياسة الخصوصية
العامة وتقييم Data Safety.

## سياسة المحتوى

الصفحات الست تحمل:

```text
default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline';
font-src 'self'; img-src 'self' data: blob:; media-src 'self' https: blob:;
connect-src 'self' https:; worker-src 'self'; object-src 'none';
base-uri 'self'; form-action 'self'; upgrade-insecure-requests
```

Meta CSP لا تدعم كل توجيهات الترويسة مثل `frame-ancestors`. عند التحويل يجب ضبط WebView
نفسه: عدم السماح بالملاحة العامة داخله، تعطيل الوصول غير اللازم للملفات، فتح الروابط
الخارجية في متصفح النظام، ومنع mixed content.

## صلاحيات Android المقترحة

- `INTERNET` للتلاوات والكتالوج.
- `VIBRATE` فقط إن استمر اهتزاز عداد الأذكار.
- لا حاجة إلى صلاحية تخزين عامة عند استخدام مساحة التطبيق الخاصة/Cache Storage.
- خدمة foreground وإشعار media playback فقط عند تنفيذ تشغيل خلفي Android فعليًا.
- تجنب الميكروفون والموقع وجهات الاتصال ومعرف الإعلان والصور والملفات العامة.

## مخاطر متبقية

1. شروط مزودي الصوت غير موثقة؛ هذه مخاطرة ملكية فكرية ونشر وليست ثغرة تقنية.
2. عناوين الصوت تأتي من كتالوجات خارجية؛ يجب الإبقاء على HTTPS وقائمة السماح في حاوية Android.
3. Cache Storage قد يُخلى تحت ضغط المساحة. النسخة الأصلية تحتاج تخزينًا ذريًا في مساحة
   التطبيق وفحص مساحة وتنظيفًا عند فشل التنزيل.
4. لم ينفذ اختبار اختراق ديناميكي على APK لأن APK غير موجود.
5. يجب إعداد Play Integrity أو certificate pinning فقط إذا ظهرت حاجة موثقة؛ لا تضفهما
   تلقائيًا إلى تطبيق محتوى عام لأنهما يزيدان التعقيد ولا يعالجان حقوق المحتوى.
